# putindorm

# Общежитие Путин

Rails-приложение интернет-магазина с калькулятором на ИИ и локальным ИИ-агентом для подготовки улучшений кода.

## Обратный отсчёт

Живая GitHub Pages-страница отсчитывает время до 26 октября 2028 года: https://mosaicin.github.io/putindorm/

## Локальный запуск

```sh
bundle install
bin/rails db:prepare
bin/rails server
```

После запуска магазин будет доступен по адресу `http://localhost:3000`. Интерфейс агента находится на `/agent` и требует входа в приложение.

ИИ-конструктор доступен на главной странице и по адресу `/calculator`, вход не нужен. В нём сразу загружается пример страницы с разноцветными ссылками и ассоциациями. Опиши изменение — ИИ обновит HTML и покажет изолированный предпросмотр; код можно редактировать вручную. Для генерации задай `GROQ_API_KEY` в локальном `.env` или переменной окружения. Не публикуй `.env`, ключи или содержимое `config/credentials.yml.enc`.

## Бесплатный пробный деплой

Конфигурация `render.yaml` предназначена для Render Free и PostgreSQL в Neon Free. Это вариант для хобби и демонстраций, не для критичного production:

- Render усыпляет бесплатный веб-сервис после 15 минут без трафика; первый запрос после простоя может ждать около минуты.
- Файловая система Render Free временная, поэтому production-база подключается отдельно через Neon.
- Neon Free включает 1 ГБ хранилища и 100 CU-часов вычислений на проект в месяц; база автоматически уходит в сон после простоя. Условия тарифов могут меняться.
- Бесплатный URL вида `*.onrender.com` постоянен, пока сервис существует. Собственный домен приобретается отдельно.

### Первое развёртывание

1. В [Neon Console](https://console.neon.tech/) открой проект и выбери нужную ветку, например `производство`. В **Databases** создай в этой ветке базы `putindorm_cache`, `putindorm_queue` и `putindorm_cable`; стандартную основную базу проекта оставь как есть (обычно это `neondb`).
2. В верхней панели нажми **Connect** и выбери ветку, compute, базу и роль. Для каждой из четырёх баз скопируй connection string с выключенным **Connection pooling**. Rails запускает миграции при старте, поэтому для этих URL нужен прямой endpoint (имя хоста без `-pooler`). Не добавляй строки подключения в Git или чат.
3. Создай аккаунт в [Render](https://dashboard.render.com/) и подключи GitHub-репозиторий `mosaicin/putindorm`.
4. В Render выбери **New → Blueprint**, укажи этот репозиторий и ветку `main`. Render найдёт `render.yaml` и предложит создать веб-сервис `putindorm`.
5. При создании добавь секреты:
   - `DATABASE_URL` — прямой connection string основной базы с `sslmode=require`.
   - `CACHE_DATABASE_URL`, `QUEUE_DATABASE_URL`, `CABLE_DATABASE_URL` — прямые connection strings соответствующих баз. Для каждой базы копируй строку через **Connect**, не меняй имя базы вручную.
   - `RAILS_MASTER_KEY` — значение из локального `config/master.key`. Не добавляй сам файл в Git.
6. Запусти Blueprint. При первом запуске контейнер выполнит `bin/rails db:prepare`. Дождись успешного деплоя и открой URL сервиса из панели Render.
7. Если нужен ИИ-калькулятор, отдельно добавь `GROQ_API_KEY` в **Render → сервис → Environment**. Не копируй ключ в репозиторий.

### Управление магазином

- Главная страница, каталог и форма добавления товара доступны посетителям без входа. Для просмотра отдельной карточки, редактирования и удаления товара войди по адресу `/session/new`.
- При первом запуске создай учётную запись в **Render → сервис → Shell**, запусти `bin/rails console`, затем введи:

  ```ruby
  require "io/console"
  print "Email: "
  email = STDIN.gets&.chomp
  print "Password: "
  password = STDIN.noecho(&:gets)&.chomp
  puts
  User.create!(email_address: email, password: password)
  ```

  Выбирай уникальный пароль и не публикуй его. Любой созданный пользователь сейчас может управлять товарами; отдельных ролей администратора в приложении пока нет.
- После отправки изменений в `main` Render автоматически соберёт и развернёт новую версию. Миграции выполняются командой `db:prepare` при старте.
- Логи и статус деплоя доступны в панели Render в разделах **Logs** и **Events**. Переменные окружения и секреты меняются через **Environment**; после изменения Render перезапускает сервис.
- Данные товаров и пользователей хранятся в Neon. Следи за лимитами Free и периодически делай резервные копии через экспорт PostgreSQL; бесплатный тариф не заменяет резервное копирование.
